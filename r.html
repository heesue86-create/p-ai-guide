03

터미널,
왜 배우는 거예요?

먼저 이걸 알아야 나머지가 이해됩니다.

통계를 돌리는 데는 터미널이 거의 필요 없습니다.
터미널을 배우는 건 GitHub을 쓰려니 따라오는 것이에요. 목적이 다른 도구입니다. 그걸 모르고 들으면 "이걸 왜 하지?"가 됩니다.

01터미널이 뭔가

탐색기(내 PC)로 폴더를 열어보는 것과 똑같은 일을, 마우스 대신 글자로 하는 창입니다. 같은 집을 창문 두 개로 보는 것 — 하나는 아이콘으로, 하나는 글자로.

02제일 헷갈리는 것 — 지금 내가 어디 서 있나

탐색기는 지금 보는 폴더가 눈에 보입니다. 터미널은 안 보입니다. 초보가 헤매는 이유는 거의 이것 하나예요. 그래서 명령 네 개면 충분합니다.

치는 것무슨 뜻탐색기로 치면
pwd나 지금 어디 있어?주소창 확인
ls여기 뭐 있어?폴더 안 보기
cd 폴더이름저기로 가자폴더 더블클릭
cd ..한 칸 위로뒤로 가기

이 넷은 아무것도 망가뜨리지 않습니다. 보기만 하는 명령이에요. 마음껏 쳐보셔도 됩니다.

SHORTCUT

터미널은 RStudio 안에 이미 있습니다

따로 검은 창을 열 필요 없어요. RStudio 화면 왼쪽 아래, Console 탭 옆에 Terminal 탭이 있습니다.

.Rproj로 열었으면 위치가 이미 맞춰져 있어서 cd로 폴더를 찾아 헤맬 일이 없습니다. 수업에서 나오는 명령을 여기 그대로 치세요.

03알아두면 덜 당황하는 것 3가지

  • 엔터를 쳐야 실행됩니다. 타이핑만으로는 아무 일도 안 일어나요. 다 치고 엔터.
  • 아무 반응이 없으면 성공한 겁니다. 터미널은 잘 되면 조용해요. 빨간 글씨가 없으면 된 것입니다. "왜 아무것도 안 나오지?"가 정상입니다.
  • 대소문자와 띄어쓰기를 구분합니다. 안 될 때 열에 아홉은 오타예요.

04수업에서 나오는 깃 명령 4개

터미널에서 배우는 건 결국 이 넷입니다. 순서는 항상 pull → 작업 → add → commit → push.

명령하는 일언제
git clone 주소인터넷 창고에서 내 PC로 처음 한 번 가져오기맨 처음 딱 한 번
git pull창고에 바뀐 게 있으면 받아오기작업 시작할 때
git add .
git commit -m "메모"		내가 바꾼 것을 "여기까지 했음"으로 묶기한 덩어리 끝냈을 때
git push묶은 것을 창고에 올리기작업 끝낼 때
CAUTION

하나만 조심하세요

rm 으로 시작하는 명령은 지우는 명령입니다. 휴지통을 거치지 않고 바로 사라져서 되돌릴 수 없어요.

수업에서 rm 이 나오면 따라 치기 전에 손 들고 물어보시거나, 아래 문장으로 먼저 확인하세요.

3) 고치는 코드
4) 다음에 안 나게 하는 법 한 줄
이 순서로 알려줘. 한 번에 한 가지만.

06

빨간 글씨
사전

자주 나오는 것만. 대부분 여기 있습니다.

화면에 이런 말이 있으면무슨 뜻어떻게
there is no package called 그 앱을 아직 안 깔았음 install.packages("이름")
could not find function 깔긴 깔았는데 안 켰음 library(이름)
object ... not found 그 이름의 자료가 없음. 오타이거나 아직 안 만듦 철자·대소문자 확인. R은 Data와 data를 다르게 봄
cannot open file
No such file or directory		 파일을 못 찾음 .Rproj로 열었는지 먼저 확인. 그 다음 파일이 그 폴더에 있는지
unexpected ')' · unexpected symbol 괄호나 따옴표 짝이 안 맞음 줄 왼쪽 빨간 X 표시된 곳부터 확인
콘솔에 + 만 계속 뜸 명령이 안 끝났다고 R이 기다리는 중 ESC 키 한 번
글자가 ??? 나 깨져 보임 한글 인코딩 문제 딸에게 연락 (설정 한 줄이면 끝남)
command not found
(터미널)		 명령 이름이 틀렸거나, 그 프로그램이 안 깔림 철자·띄어쓰기 확인. 그래도 안 되면 딸에게 연락
not a git repository
(터미널)		 깃 폴더 바깥에서 깃 명령을 침 RStudio의 Terminal 탭에서 치면 해결됨
Warning 으로 시작하는 글씨 오류가 아닙니다. "이런 점은 알고 계세요" 정도의 알림 결과가 나왔으면 그냥 진행
Error 와 Warning 은 다릅니다.
Error = 멈췄음. 고쳐야 함.
Warning = 굴러갔음. 참고사항.
빨간 글씨가 다 사고는 아니에요.
07

논문 쓸 때
3가지 약속

이 세 개만 지키면 나중에 문제가 생기지 않습니다.

MUST

지키면 심사에서 걸리지 않습니다

  1. 숫자는 반드시 내가 돌린 결과.
    Claude가 대화창에서 만들어준 숫자는 논문에 쓸 수 없습니다. 어떻게 나왔는지 되짚을 수가 없기 때문입니다. 코드를 돌리고, 나온 결과를 붙여넣고, 해석만 도움받기.
  2. 원본 데이터는 절대 건드리지 않기.
    01-원본데이터 폴더 안의 파일은 열어보기만. 고칠 일이 생기면 반드시 사본을 만들어서 02-분석코드 쪽에서 작업합니다. 원본이 한 번 덮어써지면 처음부터 다시입니다.
  3. 논문 문장은 내가 먼저 쓰기.
    Claude는 이미 쓴 문장을 다듬는 데까지. 빈 화면에서 대신 쓰게 하지 않습니다. 그리고 학교마다 AI 사용 규정이 있으니 학과에 한 번 확인해 두세요.

참고코드 도움은 대부분 허용됩니다

AI로 코드를 짜고 에러를 고치는 것은 대체로 문제되지 않습니다. 선을 넘는 지점은 본문을 대신 쓰게 하는 것과 돌리지도 않은 숫자를 싣는 것입니다. 이 두 가지만 안 하면 됩니다.
